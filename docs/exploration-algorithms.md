# 요리 탐색과 경험 지도

## 화면과 데이터

- `/search`: 비슷한 요리 / 새로운 요리 모드와 시간 제한, 5·8·10개 추천.
- `/profile`: 경험 지도를 먼저 보여줍니다. 모든 요리를 두 축에 표시하고 해본 요리는 초록색으로 강조합니다.
- ‘영역 보기’가 켜지면 경험 점의 Convex Hull을 표시하고, 내부·경계의 미경험 요리를 오른쪽에 표시합니다.
- 축 조합별 영역 포함 횟수 순위도 5·8·10개 중 선택한 수만큼 표시합니다. 후보가 적으면 실제 후보 수만 표시합니다.
- 요리 경험은 `cooked_recipes(user_id, recipe_id)`에 저장합니다. 로그인된 사용자만 자신의 기록을 추가·취소할 수 있습니다.
- backend `/explore`는 실제 레시피와 `backend/data/recipe-metadata.json`의 동일 `name` 객체를 연결합니다.
- 추천, 좌표 정규화, 넓이, 포함 판정은 브라우저에서 계산합니다. 서버가 계산한 추천 순위나 외부 AI API를 사용하지 않습니다.
- 이름 검색은 `/search`와 `/recipes`에 연결되었습니다. 단계별 DP는 포함하지 않습니다.

## 현재 데이터 연결

현재 DB와 메타데이터의 실제 형식에 맞춰 연결했습니다. 상세 규칙은 [검색과 그래프 데이터](search.md)를 참고하세요.

- 조리 시간은 DB `estimated_time`에서 분으로 변환합니다.
- 재료 수는 DB `ingredients`의 쉼표·줄바꿈으로 구분된 항목 수입니다.
- 조리 단계 수는 DB `recipe`의 1부터 순서대로 매겨진 번호 개수입니다.
- 난이도는 `recipe-metadata.json`의 **1~10 정수**입니다. 문자형 쉬움/보통/어려움을 요구하지 않습니다.
- 별도 `step_count` 입력은 필요하지 않습니다. API가 본문에 명시된 단계 번호를 셉니다.
- 난이도 등 확인할 수 없는 값은 null이며 임의 난이도를 생성하지 않습니다.

## 1. 넓이 계산

`frontend/src/lib/exploration.ts`의 `hull`, `area`, `inside`:

1. 좌표 정렬과 중복 제거.
2. CCW 외적 판정으로 Monotone Chain Convex Hull 계산: O(m log m).
3. 신발끈 공식으로 면적 계산: O(m).
4. 모든 변의 CCW 부호로 내부·경계 포함 판정. 면적이 0인 도형은 영역으로 취급하지 않음.

추천 계산에서는 카탈로그 전체의 축별 최솟값·최댓값을 기준으로 0~1 정규화합니다.
값이 일정한 축은 추천 공간에서 제외합니다. 후보를 고르거나 시간 필터를 바꿔도 기준 범위는 바뀌지 않습니다.
각 유효한 축 쌍에서 후보 추가 전후 넓이 차이를 구하고, 평균을 `gain`으로 사용합니다.
여러 면적을 곱하지 않으므로 한 평면의 면적이 0인 경우가 전체 점수를 0으로 만들지 않습니다.

## 2. 넓이 + 그리디 추천

거리 `novelty`는 정규화 좌표의 RMS 유클리드 거리 중 기준 집합까지의 최소값입니다.
현재 거리는 시간·재료 수·단계 수·난이도의 차이를 뜻합니다. 같은 재료나 같은 조리법을 쓴다는 의미의 유사도는 아닙니다.

새로운 요리:

`score = 0.65 × gain + 0.35 × novelty`

가장 높은 후보를 하나 선택하고 임시 기준 집합에 추가합니다.
남은 후보의 Convex Hull 확장량과 최소 거리를 재계산하는 과정을 k번 반복합니다.
비슷한 후보를 계속 고르지 않도록 이미 선택한 추천도 다음 점수에 영향을 줍니다.

비슷한 요리:

`score = 0.55 × (1 - gain) + 0.30 × (1 - novelty) + 0.15 × diversity`

`gain`과 `novelty`는 실제 경험 집합을 기준으로 유지합니다.
`diversity`는 이미 추천한 요리까지의 최소 거리이며 첫 선택에서는 0입니다.
이 값은 한 개를 고를 때마다 갱신하여 익숙함을 유지하면서 목록의 중복을 줄입니다.

경험 점이 적거나 일직선이어서 유효 면적이 없으면 거리로 시작합니다.
새로운 요리는 `novelty`, 비슷한 요리는 `0.85 × (1 - novelty) + 0.15 × diversity`를 사용합니다.
새로운 요리 모드에서 선택이 쌓여 도형을 만들 수 있으면 이후 단계부터 넓이 점수를 사용합니다.
경험 기록 자체가 없으면 임의 개인화 추천을 만들지 않고 경험 입력을 안내합니다.

해본 요리와 이미 선택한 후보는 재추천하지 않습니다. 점수 동률은 ID 오름차순입니다.
그리디 계산의 임시 선택은 DB의 실제 경험 기록을 변경하지 않습니다.
현재 가중치는 실험용 초기값이며 전역 최적해나 사용자 만족도를 보장하지 않습니다.

단순 구현은 후보 n개, 축 쌍 p개, 경험 m개, 추천 k개일 때 대략 O(k·n·p·(m+k)log(m+k))이며 작은 카탈로그에 적합합니다.

## 3. 여러 축의 익숙함 순위

순서 없는 모든 축 쌍 조합을 생성합니다(4개 축이면 최대 6개).
실제 경험만으로 각 헐을 구성하고, 넓이가 0인 조합을 제외합니다.
미경험 후보가 내부 또는 경계에 들어가는 횟수를 세어 내림차순 정렬합니다.
횟수 동률은 ID 오름차순이며, 포함 횟수 0인 요리는 ‘익숙한 요리’로 표시하지 않습니다.
모든 후보가 동일한 유효 축 조합으로 평가되도록 값이 누락된 후보는 이 순위에서 제외합니다.

이는 ‘선택한 특성들에서 얼마나 자주 내 범위 안에 있는가’를 나타냅니다.
상관된 축이 비슷한 정보를 반복 반영할 수 있고, 헐은 두 경험 군집 사이의 미경험 공간도 포함할 수 있습니다.
실제 난이도, 요리 성공 확률, 전체 고차원 공간의 내부 여부를 보장하는 지표가 아닙니다.
